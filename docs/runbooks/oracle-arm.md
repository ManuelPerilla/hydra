# Producción Oracle ARM

La configuración Terraform se valida sin credenciales; un despliegue real requiere una cuenta Always Free, capacidad A1, claves OCI y elegibilidad revisada. No se ha aplicado en una cuenta cloud durante el desarrollo local.

1. Instala Terraform y configura el SDK oficial OCI con claves de tu cuenta en `~/.oci/config`, usando su región principal. Instala `oci` en un entorno Python aislado.
2. Revisa la consola: cuenta Always-Free-only, cuotas de toda la cuenta, almacenamiento, backups, egreso y tipos elegibles. Ejecuta `python scripts/oci-preflight.py --always-free-only --paid-resources-reviewed`. El inventario aborta si no puede leer todos los compartimentos y caduca tras una hora.
   Para actualizar un despliegue existente, exporta `terraform -chdir=infra/terraform/environments/oracle show -json` a `.local/oci-state.json` y añade `--terraform-state .local/oci-state.json` al preflight. Esa copia puede contener datos sensibles; protégela y no la subas a Git. Solo IDs exactos del módulo runtime, comprobados contra OCI y etiquetas Hydra, se descuentan para evitar contar la propia instalación dos veces. Un state antiguo o un recurso inaccesible detiene el inventario.
3. Copia `terraform.tfvars.example` en `infra/terraform/environments/oracle` y completa datos reales. No lo añadas a Git. Ejecuta init y plan; revisa el plan antes del apply. Las confirmaciones de elegibilidad no se infieren del inventario.
4. Terraform crea una A1 2 OCPU/12 GB, boot50 + datos50, red, IP reservada y k3s. Cloud-init formatea únicamente el volumen de datos designado cuando no tiene filesystem ni firma reconocida, monta `/srv/hydra` y guarda ahí el estado k3s y local-path. K3s exige el montaje también tras reiniciar; no arranca sobre el disco boot si falla. La unidad de firewall repone solo las reglas Hydra de80/443 en cada arranque. Nunca cambia a un shape pagado si falla capacidad.
5. Accede por SSH desde el CIDR autorizado. La API Kubernetes queda privada; administra mediante SSH o un túnel SSH, sin abrir 6443 al mundo.
6. En un overlay de release, sustituye las tres imágenes `:dev` por los digests reales publicados para API/agente/web. Verifica manifests amd64/arm64 y descarga anónima: GHCR crea paquetes inicialmente privados, aunque el repositorio sea público; configura los tres paquetes como públicos antes de desplegar sin imagePullSecrets. Genera `hydra-runtime` fuera de Git con password, token y key32bytes; configura OAuth GitHub, IDs numéricos permitidos y la key del secret `PUBLIC_URL=https://IP`, que alimenta `Hydra__PublicOrigin`. Callback exacto: `https://IP/auth/github/callback`.
7. Crea `/srv/hydra/acme`, aplica ACME overlay y configura Certbot>=5.4 en `/opt/hydra/acme`. Instala `renew-ip.sh` como `/usr/local/sbin/hydra-renew-ip`; configura IP/email en `/etc/hydra/certificate.env`. Instala service/timer y habilita renovación diaria. Usa staging para la primera prueba; valida expiración y renovación antes de producción.
   El challenge usa PV/PVC sobre el volumen montado y un pod restringido. El nodo debe tener `hydra.io/storage=oracle-data`, aplicado por cloud-init. `TLSStore/default` presenta el certificado IP incluso sin SNI: compruébalo con `openssl s_client -connect IP:443 -noservername -verify_ip IP -verify_return_error`. No habilites OAuth hasta que el certificado emitido sea válido y la verificación pase.
8. Ejecuta dry-run, comprueba que solo el agente puede borrar pods de `chaos-demo`, prueba reconnect y restore. Publica consumo medido y límites conocidos.

La API tiene replicas, pero host/control plane/PostgreSQL no son redundantes. Oracle puede reclamar recursos ociosos. Conserva backups cifrados independientes y prueba redespliegue; no generes carga artificial para evitar esa política.

Terraform protege VM, IP y datos con `prevent_destroy`. Su retiro requiere revisar explícitamente qué se conserva y los backups; no ejecutar destroy indiscriminado. Las alertas de presupuesto no bloquean facturación. Este perfil no incluye OKE, NAT Gateway ni servicios gestionados de pago obligatorios.

La configuración de paquetes públicos y sus permisos se describe en [GHCR](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry). Los workflows están preparados; aún no se han ejecutado en un repositorio remoto.
